# 100マス計算アプリ　全体設計書

**版：基本構想 v1.1**  
**対象：全国の公立・私立小学校**

## 1. 開発の目的

児童が100マス計算に継続して取り組み、自分の成長を実感できること。そして先生が、児童一人ひとりの学習状況とクラス全体の傾向を把握し、次の指導に生かせることを目指す。

単なる計算練習アプリではなく、次の2つを両立する。

- **児童にとって：** 楽しく、無理なく続けられ、自分の成長が見える。
- **先生にとって：** 問題を配布し、結果を自動で集約・確認できる。集計作業を増やさない。

開発では、機能を増やすこと自体を目的とせず、必要な機能を小さく実装し、実際の学校現場で確かめながら改善する。

## 2. 想定する利用者

| 利用者 | 主な役割 |
|---|---|
| 学校管理者 | 学校の利用環境・利用者を管理する |
| 先生 | クラス作成、問題作成・配布、結果確認 |
| 児童 | 配布された問題に取り組み、結果を送信する |

児童は当初ログイン不要とし、クラスと出席番号を入力して利用する。先生用画面には認証を設ける。認証方式はGoogleアカウント連携を候補としつつ、学校のGoogle Workspaceで外部認証が制限される可能性も考慮し、導入しやすい方式を比較して決定する。

## 3. 基本方針

1. 全国の公立・私立小学校で利用できる設計にする。
2. 学校・先生・クラスを区別してデータを管理する。
3. **クラスごとに異なる問題セットを設定できる**ようにする。
4. 児童はログインせず、クラスと出席番号を入力して問題に取り組める。
5. 解答結果は最初の段階からサーバーに送信し、クラス単位で自動集約する。
6. 児童の氏名・メールアドレス・生年月日などは原則収集しない。クラス・出席番号と学習結果の組み合わせも児童を識別し得る情報として慎重に扱う。
7. 将来、児童ごとのログインやGoogle Classroom連携を追加できる構造にする。
8. 現在のアプリを一度に作り直さず、段階的に移行する。

## 4. 利用の流れ

### 先生側

1. 先生がログインする。
2. 学校と担当クラスを選択する。
3. クラス用の問題セットを作成・設定する。
4. 配布用URLまたはQRコードを発行する。
5. 児童にURL・QRコードを配布する。
6. 児童の解答結果が自動的に集約される。
7. 先生はクラス全体・児童ごとの結果を確認する。

### 児童側

1. 先生から配布されたURLまたはQRコードを開く。
2. クラスと出席番号を入力する（URLでクラスが指定されている場合は出席番号のみでもよい）。
3. 問題に取り組む。
4. 結果を確認する。
5. 結果がサーバーに送信され、同じクラス・出席番号の学習履歴に紐付く。

児童の操作はできるだけ少なくし、ログインや複雑な設定を求めない。

## 5. システムの構成

将来的には、次の構成を基本とする。

- **フロントエンド：** 児童用画面・先生用画面。現在のHTML/CSS/JavaScriptを活用する。
- **バックエンド：** 問題配布、結果受信、データの集約、アクセス権限の確認を行う。
- **データベース：** 学校、先生、クラス、問題セット、配布情報、解答結果を保存する。
- **認証：** 先生のログインに使用する。児童は当初ログイン不要とする。

Supabaseなどのサービスは候補として比較するが、費用・セキュリティ・学校での利用条件を確認してから決定する。

## 6. 重要な設計概念

### 問題セットと配布を分ける

- **問題セット：** どのような計算問題を出すかを定義したもの。
- **配布（課題）：** どのクラスに、いつ、どの問題セットを配るかを定義したもの。

同じ問題セットを複数クラスで利用する場合でも、クラスごとに別の配布情報を作る。

配布後に問題セットを変更しても、過去の結果と問題内容の対応関係が崩れないよう、配布時点の問題内容を固定する。

### 問題の同一性

同じ条件・同じ問題セット番号であれば、同じ問題が再現できる仕組みを維持する。問題セットには、画面に表示する番号とは別に、システム内部で一意となるIDを持たせる。

## 7. 第1段階で実現する機能

| 分類 | 機能 |
|---|---|
| 先生 | ログイン |
| 先生 | クラスの登録・管理 |
| 先生 | クラスごとの問題セット作成 |
| 先生 | URL・QRコードによる配布 |
| 児童 | ログインなしで問題に取り組む |
| 児童 | クラス・出席番号による識別（内部では児童IDに変換） |
| システム | 解答結果のサーバー送信 |
| 先生 | クラス全体の結果一覧 |
| 先生 | 児童ごとの履歴・成長確認 |
| 先生 | クラス結果のCSV出力（表計算ソフトで利用可能） |

最初から多機能な分析画面を作る必要はない。まずは、結果が確実に保存され、クラス全体と児童ごとの記録を確認できることを優先する。

## 8. 結果の出力

先生用画面から、担当クラスの結果をCSV形式で出力できるようにする。CSVはExcelやGoogleスプレッドシートに取り込みやすい文字コード・形式とし、クラス全体または児童別・期間別に出力できる設計とする。初期版ではCSVを優先し、XLSX形式は必要性を確認してから検討する。

出力項目の候補は、年度、学年、クラス、出席番号、課題名、問題セット、実施日時、所要時間、正解数、問題数、正答率、誤答数、訂正回数とする。氏名は初期版では含めない。

## 9. 将来追加する機能

- 学年・学校をまたいだ管理
- 児童個人のアカウント・ログイン
- Google Classroomとの連携
- 学年・学校単位の集計
- 学習状況のグラフ表示
- 問題セットの共有・再利用
- 先生同士の教材共有

## 10. 開発で大切にすること

- 現在のアプリの良い部分を残す。
- 既存の動作を確認してから変更する。
- 現行版を上書きせず、バージョンを分けて開発する。
- 児童の氏名等を収集しない場合でも、クラス・出席番号・学習結果は個人を識別し得る情報として扱う。
- 実際の児童のデータを使う試用や学校タブレットでの利用は、必要な学校・自治体の確認と承認、安全対策を済ませてから行う。開発中は架空データを使用する。
- 学校ごとのデータが他校から見えない仕組みを最初から設計する。
- 先生の作業を増やさないことを、機能の判断基準にする。

**最終的な目標：児童の学びを支え、先生の負担を減らし、全国の小学校で使える学習ツールに育てる。**
